# Implementation Plan: GitHub → Jira → Slack Bot (Slack-driven)

## Status: Implemented ✅

## Architecture

```
git push (local hook) ───────────────────────────────► POST /git/push      → Jira: In Progress
Slack #backend-review-code (new root msg from me) ───► POST /slack/events  → Jira: In Review (+ worklog if missing)
Slack #backend-review-code (✅ on MY message) ───────► POST /slack/events  → Jira: QA Ready (+ comment + Slack thread reply)
Slack #backend-review-code (✅ on TEAMMATE msg) ─────► POST /slack/events  → GitHub PR APPROVE for every linked PR
Slack /tickets [YYYY-MM-DD] ─────────────────────────► POST /slack/commands → list my Jira keys mentioned that day (ephemeral)
GET /jira/tickets-by-day?date=YYYY-MM-DD ────────────► same audit as the slash command, JSON + preview channel
```

## Transition Guard Logic (in `transitionIssue`)

```
1. Fetch issue from Jira (status + sprint fields)
2. Check required current status:
   - → In Progress  requires current = "To Do"
   - → In Review    requires current = "In Progress"
   - → QA Ready     requires current = "In Review"
   - other targets: no restriction
3. If → In Progress: check customfield_10010 (sprint array) — block if any sprint.id === 249
4. If → In Review: call createWorklog(issueKey) — Scrum Master rule, must precede the transition
5. Emit preview via preview() — terminal log + SLACK_PREVIEW_CHANNEL post (owner-tagged)
6. Call doTransition
7. Return true on success, false on skip or error
```

`addComment` and `createWorklog` work the same way — each emits a preview then performs the Jira call. All three (transition, comment, worklog) always execute the real Jira mutation regardless of `DRY_RUN`. Only `replyToThread` is gated by `DRY_RUN=true` (preview still emits, real Slack post is suppressed).

`createWorklog(issueKey, opts?)` is **idempotent**: it first calls `client.issueWorklogs.getIssueWorklog` and skips if any worklog already exists (`total > 0`). On fetch failure it fails open (creates anyway). Defaults: `timeSpentSeconds = 3600`, `description = 'Implement based on solution design & implementation plan, self-review, self-test'`, `started = <today in Asia/Bangkok>T12:00:00.000+0700`. Comment field is prefixed with `[Generated by personal bot]`. Errors are swallowed (logged, caller continues).

Callers check the return value — `addComment` and `replyToThread` are only called if `transitionIssue` returns `true`.

## handleReviewMessage Flow

```
1. Filter: user === MY_SLACK_USER_ID
2. Filter: channel === SLACK_REVIEW_CHANNEL
3. Filter: root message (no thread_ts or thread_ts === ts)
4. Strip Slack angle-bracket URL wrapping: <https://...> → https://...
5. Match GitHub PR URL regex
6. extractJiraKey from message text
7. If no key: fetchPrTitle(prUrl) → extractJiraKey from title
8. transitionIssue(key, ID_IN_REVIEW)
```

## reaction_added Dispatch

The `/slack/events` route filters `reaction === 'white_check_mark'` and channel `SLACK_REVIEW_CHANNEL`, then routes by `event.item_user`:

- `item_user === MY_SLACK_USER_ID` → `handleReactionAdded` (QA Ready flow)
- otherwise → `handleApproveReaction` (PR approve flow)

### handleReactionAdded Flow (✅ on my own message)

```
1. fetchMessage(channel, ts) → original message text
2. Strip angle-bracket URL wrapping, match GitHub PR URL regex (else stop)
3. fetchPrData(prUrl) → { title, baseBranch }
4. Allow only baseBranch ∈ {develop, releasing_staging, main, master}
5. Resolve Jira keys to process:
   - If baseBranch === "releasing_staging":
       fetchPrCommits(prUrl) → filter by (authorLogin === MY_GITHUB_USERNAME || committerLogin === MY_GITHUB_USERNAME)
       → extractJiraKey(message) → unique → array of keys
       (committer match catches cherry-picks where you applied someone else's commit)
   - Else: extractJiraKey(message text) || extractJiraKey(PR title) → single key
6. For each jiraKey, processQaReadyTicket(jiraKey, baseBranch):
   a. Wait QA_NOTIFY_DELAY_MINUTES (delay applies to the transition itself, not just the notifications)
   b. transitionIssue(key, ID_QA_READY) → if false, return
   c. If baseBranch ∈ {main, master}: stop here (transition only)
   d. env = baseBranch === 'releasing_staging' ? 'STAGING' : 'DEV'
   e. addComment(key, `Ready for QA testing on ${env}`)
   f. getIssue(key) → if Bug: extractSlackThread(description) → replyToThread(`Dạ card này test được ở ${env} rồi ạ`)
```

### handleApproveReaction Flow (✅ on teammate message)

```
1. fetchMessage(channel, ts) → original message text
2. Extract all GitHub PR URLs (dedupe). If none, stop.
3. For each prUrl: approvePr(prUrl) → preview ✅/⚠️ result (untagged)
   - Ignores DRY_RUN: approvals always run.
```

## Audit (/tickets and GET /jira/tickets-by-day)

```
1. Resolve day (YYYY-MM-DD); default today in Asia/Bangkok
2. searchMyMessages(`from:<@MY_SLACK_USER_ID> on:${day}`) via user token (search.messages)
3. Filter out messages whose channel.id ∈ IGNORED_AUDIT_CHANNELS
4. Flat-dedupe Jira keys across all kept messages (first-occurrence order)
5. Promise.all → getIssueSummary(key) for each key (null on failure)
6. formatAuditReport → one ticket per line: <JIRA_HOST/browse/KEY|KEY>: summary
7. Slash command: ack ephemeral "Running" within 3s, then POST report to response_url (ephemeral)
   GET endpoint: emit preview to SLACK_PREVIEW_CHANNEL (untagged), return JSON
8. Slash command silently 200s for any user_id !== MY_SLACK_USER_ID
```

## Slack Signing Verification

```
basestring = "v0:" + X-Slack-Request-Timestamp + ":" + rawBody
digest = "v0=" + hmac_sha256(SLACK_SIGNING_SECRET, basestring)
compare with X-Slack-Signature using timingSafeEqual
Reject if |now - timestamp| > 300s
Skip Slack retries (X-Slack-Retry-Num header)
```

## post-push Hook Logic

```
1. Get current branch
2. Skip if branch is HEAD / main / master / develop
3. Check if remote ref had prior history (git rev-parse refs/remotes/origin/BRANCH@{1})
4. If no prior history → first push → extract Jira key from commit message or branch name
5. POST {jiraKey} to $BOT_URL/git/push
6. Failures are non-fatal (--max-time 5, fallback echo)
```

## Preview & Dry Run Mode

`preview(text, opts?)` always logs `[PREVIEW] ...` to terminal and (if `SLACK_PREVIEW_CHANNEL` is set) posts to that channel. Default suffixes the text with `\n<@MY_SLACK_USER_ID>` for a Slack ping; opt out with `{ tag: false }` (currently used by audit reports and PR-approve previews). The replyToThread preview includes a clickable archive URL when `SLACK_WORKSPACE` is set.

`DRY_RUN=true` only suppresses the real `chat.postMessage` call inside `replyToThread`. Jira transitions, comments, worklogs, and PR approvals still execute. Preview output is unaffected by `DRY_RUN`.

## Slack App Scopes Required

**Bot Token Scopes** (`xoxb-...` → `SLACK_BOT_TOKEN`):

| Scope | Why |
| --- | --- |
| `chat:write` | Post messages in channels the bot is in (preview channel, thread replies) |
| `chat:write.public` | Post in public channels without joining |
| `channels:history` | Read messages in public channels (e.g. fetch original message for ✅ reaction) |
| `groups:history` | Read messages in private channels |
| `reactions:read` | Receive `reaction_added` events |
| `commands` | Receive slash command payloads at `/slack/commands` |

**User Token Scopes** (`xoxp-...` → `SLACK_USER_TOKEN`):

| Scope | Why |
| --- | --- |
| `search:read` | Used by `/tickets` to find your messages workspace-wide via `search.messages` |

## Deployment Checklist (Railway)

1. Set all env vars in Railway Variables tab (see CLAUDE.md env table — in particular `SLACK_BOT_TOKEN`, `SLACK_USER_TOKEN`, `SLACK_SIGNING_SECRET`, `JIRA_*`, `GITHUB_TOKEN`, transition IDs)
2. Deploy → get public URL
3. Slack App → Event Subscriptions → Request URL → `https://<app>.railway.app/slack/events`
4. Subscribe bot events: `message.channels`, `message.groups`, `reaction_added`
5. Slash Commands → create `/tickets` with Request URL `https://<app>.railway.app/slack/commands`
6. Reinstall app to workspace after scope changes (rotates both bot and user tokens)
7. Install git hook in each repo: `ln -sf $(pwd)/hooks/post-push /path/to/repo/.git/hooks/post-push`
8. Set `BOT_URL=https://<app>.railway.app` in prod `.env`
9. Set `DRY_RUN=false` when ready to actually post Slack thread replies
